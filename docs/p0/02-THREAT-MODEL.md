# 威胁模型与攻击路径

AgentGuard V2.0 · P0-3 · 2026-11-05

## 目的

从攻击者视角分析模型、运行时、适配器、策略、UI、审计和 OS 边界。以下为架构推导及待验证威胁，接口事实引用来源登记。[能力调查](04-AGENT-CAPABILITY-MATRIX.md)

## 结论

安全设计必须同时考虑不可信操作输入与执行方绕过。合作式 Hook 可以阻止受管调用，面对被污染的宿主、全信任插件或同用户恶意进程，需要独立 OS 边界。普通用户态后台进程与哈希链无法独立抵抗同权限攻击者或管理员。

第一版的安全保证绑定精确版本、执行入口和有效沙箱。每次决策输出 coverage 和 unknowns，缺少强制点时拒绝宣称失败关闭。以下残余风险由安全状态明确呈现。

## 资产及数据分级

| 资产 | 安全属性 | 默认策略 |
|---|---|---|
| 项目源代码与用户文件 | 保密性、完整性、可恢复性 | 只授权指定项目和操作，写前预览，备份能力另验 |
| SSH 私钥、API Key、GitHub Token | 机密、可撤销性 | 不采集内容，不允许工具主动探测或上传 |
| 云服务器凭证、数据库密码 | 机密、环境隔离 | 默认禁止生产连接及凭证访问，人工审批不得越硬禁 |
| 系统配置、认证信息 | 完整性、账户控制 | 默认禁止持久安全弱化、身份窃取和提权 |
| 授权数据库与 IPC 密钥 | 防伪造、防重放 | Core 独占、最小句柄、短期许可 |
| 原始操作、日志与回放 | 完整性、隐私、顺序 | 脱敏后落盘、来源分级、缺口显式化 |
| AgentGuard 二进制/策略/更新包 | 供应链完整性 | 签名与发布摘要校验，降级需明确流程 |

## 对手能力

T0 为诱导合法 Agent 的外部文本。T1 控制恶意工具/MCP/依赖。T2 控制 Agent Host 或同一 Windows 用户的进程。T3 控制管理员、内核或宿主 OS。第一版重点减少 T0/T1 在已验证路径上的损害，T2 仅在独立受限执行环境覆盖内建立保护，T3 不纳入可兑现保证。

威胁表中的概率和影响采用定性评估，属于设计判断。

| ID | 威胁来源与攻击步骤 | 影响/优先级 | 防御及验证 | 残余风险 |
|---|---|---|---|---|
| T01 | 恶意模型把清理任务改为删除用户目录 | 高/P0 | 硬禁根目录、范围核对、单次授权，AT02/11 | 已授权目录内仍可能删错 |

| T03 | 网页/MCP 提示注入要求上传私钥 | 严重/P0 | 来源污点、敏感路径硬禁、出站目标/数据授权，AT10/26 | 同用户未隔离 Host 可直接上传 |
| T04 | 恶意仓库 hooks/任务脚本伪装成测试 | 高/P0 | 项目内容不授信，脚本及解释器摘要绑定，AT06/07 | 脚本运行时下载/读取变化不可纯静态预测 |
| T05 | npm/pip 包安装脚本执行持久化 | 高/P0 | 依赖安装单列高风险，离线隔离工具链，AT07/35 | 包运行后的行为需 OS 约束 |

| T17 | read-only 命令含配置执行、外部 diff 或重定向 | 高/P0 | 已审查 exec recipe，未知降人工，AT03/04 | 命令名白名单无法表达语义 |
| T18 | 队列洪水、磁盘满、故意无效事件隐藏后续危险操作 | 高/P0 | 控制/观察队列隔离、配额、丢失计数、满盘拒绝，AT21/29 | 观察数据无法恢复即保留缺口 |
| T19 | DNS 变化/重定向/代理/localhost 转发绕过域名授权 | 严重/P0 | 每跳验证和强制出站代理/OS 拒绝直连，AT10/31 | 普通用户态代理不阻止任意直连 |
| T20 | 撤销后仍用原生长期权限、缓存许可或后台任务 | 高/P0 | 不写原生永久规则、撤销 epoch、停用受控执行租约，AT18/33 | 已执行数据外泄无法撤销 |
| T21 | 更新/回滚注入旧易受攻击 adapter | 高/P0 | 精确构建清单、防回退最低版本、重新认证，AT20 | 分发签名密钥被盗需外部处置 |
| T22 | 日志/解释器看到秘密并进入新模型上下文 | 高/P0 | 采集最小化、脱敏后解释、禁止远端默认调用，AT34 | 单纯 pattern 脱敏存在漏报 |

## 安全目标及不变量

G1 未授权操作不能因 AgentGuard 的解释或“未知”等级被自动批准。G2 授权具有主体、目标、参数、次数、时限和撤销条件。G3 先持久记录授权再回复可执行许可。G4 请求、批准、执行、成功分开。G5 失败和缺口可见。G6 监控器没有通用提权或任意命令接口。

G1 在强制边界内作为必须证明的不变量。边界外未接入操作是已记录覆盖缺口，不能以“Core 默认 deny”声称已经阻止。

## 技术依据

DSH 的 Host 插件位于工作区沙箱外，Reasonix runtime Extension 属于 full trust。Codex 部分 Hook 错误可继续。Named Pipe 默认权限和 Windows 同 SID 访问模型要求额外身份防护。[S01、S18、S25、S40、S44–45](13-SOURCE-REGISTER.md)

## 风险

恶意进程可攻击普通用户态监控器，能够联网的 Agent Host 自身也可能泄露上下文。建立工具网关并不自动控制模型连接、浏览器连接器和远端执行。

## 尚未确定的内容

各 Host 能否把全部相关执行放入可靠隔离，GUI 自动化兼容性、强制出站控制、独立审计锚点及审批防伪能力。详细门槛见开放问题。[开放问题](12-OPEN-QUESTIONS.md)
