# I06-D 安全审查与风险登记

本次检查固定快照、角色调用顺序、MAC、epoch、截止点、nonce 唯一性、状态终止及查询无重发。合成角色和时钟由测试调用者提供，真实身份与可信时间源要在后续阶段独立核验。

| 风险或未覆盖范围 | 当前证据与边界 |
|---|---|
| 已认证角色、资源和变更通知 | 内部对照能够拒绝替换。跨路由请求不能注销别人的准备记录，可信 Core 显式注销旧路由。没有运行中的认证通道与资源重新核验。 |
| 假定提交与进程恢复 | 本阶段以独占内存状态模拟提交和确认丢失。新模型没有授权恢复入口。SQLite 的历史回归独立于本实现。 |
| 敏感输入生命周期 | 活跃 Prepared 内存持有 snapshot，退休时丢弃。内存擦除、转储、生产日志脱敏与秘密发现仍待独立验证。 |
| 历史审计与密钥 | 合成 audit 单链接 MAC 验证不提供截尾或回滚证明。D 阶段仅持有当前密钥，生产历史保留策略与外部锚待决。 |
| 资源范围 | 虚拟读取限定单目标与单清单条目。文件写入、网络、进程及实际句柄生命周期没有 D 阶段正向授权路径。 |

G0 负责人接受的限制持续适用。任意同一安全主体 SQL、DDL 或数据库文件控制，恶意整体数据库回滚，生产密钥与独立信任锚，真实 Windows OS 隔离，真实 Agent／外部副作用，以及物理掉电、硬件故障和生产环境恢复均未验证。I05 的 `operation_digest` 仍是合成输入摘要。I06-D 另行计算 18 所规定的 HMAC，两者未接线。

D01 独立主体与部署、D02 Firewall/WFP、D03 GUI/COM、D04 真实委托路线、D05 密钥与防回滚锚继续待决。七款 Agent 为 L0，五项能力标志均为 false。生产安全结论仍受各自证据门禁约束。
