## 十二项设计验收答复

| 问题 | 已由现有代码证明 | 本次设计提出 | 需要未来验证或当前不可证 |
|---|---|---|---|
| 1 · 唯一权威 Writer | G0 在 fixture 锁下持有连接，经唯一队列写入。 | S 专用命令复用同一 Writer、连接与事务执行器。 | 测试同 lineage 双开、并发和 v4 启动拒绝。 |
| 2 · 持久化变更归属 | G0 状态和审计由同一事务提交。 | 所有实时授权、审计、恢复写入由 Writer 负责。测试 Marker 属于启动围栏，查询只读。 | 验证 v4 旧入口旁路、迁移及启动路径。任意同主体 SQL 或文件控制不可证。 |
| 3 · 额度一致性 | I06-D 证明模型内扣额规则，G0 当前没有 Parent Rule 用量。 | 只由数据库权威计数，在 Reserve 事务以版本和余额条件更新。 | 100 请求争用、各写点失败及计数与 claim 逐笔对账。 |
| 4 · 批准真实且未撤销 | I06-D 在测试中要求显式人工意图并绑定快照。 | Writer 登记合成 UI 的批准与版本，Reserve 和 Consume 重读活动头与撤销，单次 claim 防重用。 | 验证合成来源、撤销竞争和快照替换。真实用户身份及知情同意不可证。 |
| 5 · Reservation 不重复 | G0 有 Grant 级 Reservation 和全局 nonce 唯一性。 | S 增加 Reservation ID、Grant 和 claim 唯一关联，完整审计同提交。 | 碰撞、换 ID、事务失败和重启回归。 |
| 6 · Permit 不重复消费 | G0 可一次消费其合成状态，I06-D 已验证冻结 MAC 和内存重放。 | Writer 在同一事务验签并条件转移 reserved→consumed。 | 并发重复兑换、错 key／scope／epoch、撤销顺序及重启。 |
| 7 · 启动响应不重复签发 | 既有 G0 消费只创建执行事实，I06-D 没有真实启动响应。 | 唯一启动登记、原 reply slot 一次取用、无持久响应正文或重发。 | 提交后故障、重复响应、Broker 单次门禁及重启。外部副作用 exactly-once 不可证。 |
| 8 · COMMIT 后丢响应 | G0 可查询已持久的请求收据。 | 新耐久回复与历史视图类型分离。完整收据可证提交，缺记录保留可能未知。 | 各 COMMIT／发送断点、晚回复丢弃和独立只读取证。 |
| 9 · Core 重启后一致性 | G0 reopen 生成新 boot epoch、失效未完成 Grant 并保留审计。 | 同一启动事务加 S 失效、时钟域和 key generation 围栏。旧归档只读。 | Marker 中断、旧库恢复、Core／Writer 独立崩溃、历史完整性。恶意同时回滚 Marker 和 DB 不可证。 |
| 10 · 兼容原验收 | I06-D 基线直接包含 G0，原分支已验收。 | 保留 001–003、I06-D 公开行为及旧 v3 入口。v4 显式隔离。 | S1 候选重跑原用例与旧库兼容性，验收 SHA 重跑整套。 |
| 11 · 新的信任假设 | G0 和 I06-D 已限定同主体、合成范围。 | 信任 Core 证据生产者、密封类型、原 reply slot 以及 Writer 所有权、SQLite/VFS、测试 Marker 和 lineage 锁。 | 内部可见性审计、泄漏和错误路由测试。跨主体和 T2-B 仍不可证。 |
| 12 · 仍无法证明的能力 | 既有报告只覆盖原工程范围。 | 只声明测试事务与受控恢复的可验证目标。 | 真实 Agent 和跨主体隔离、生产密钥及锚、恶意整体回滚、任意同主体数据库控制、外部副作用单次性、物理掉电和生产恢复仍不可证。 |
