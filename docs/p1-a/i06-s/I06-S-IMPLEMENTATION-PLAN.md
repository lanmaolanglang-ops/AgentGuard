# I06-S 实施计划与待批准接口

**S0 设计尚未冻结。** 以下为负责人可复核的解阻方案，具体接口和迁移未实施。[依赖与偏差证据](I06-S-DEPENDENCY-REPORT.md)

## 最小接口提案

1. 在既有 Writer 内新增一个 S 专用、封闭且有类型的事务入口。保留 G0 原入口、三份迁移和测试。批准、Parent Rule 版本与扣额、Reservation 唯一键、Peer／Prepared／generation、双截止点、Grant 转移和审计在同一 Writer 事务内核对。正式 HMAC 用独立字段保存，与原 I05 输入摘要分别验证。
2. 从 I06-D 提供仅供 Core 的准备／校验接口，复用现有 payload、Grant 迁移规则和验签。明确区分预提交候选和确认提交后的出站响应。由 Writer 事务核验实际时钟与绑定，提交失败或结果未知时冻结该尝试。需要负责人确认允许增加这种适配入口，原 24 项用例和既有公开行为仍作为回归边界。
3. S 专用附加迁移拟加入单次人工意图、规则额度、Reservation／执行绑定、结果证据和收据关联，保留 003 原文及已验收库。候选迁移先在新 fixture 副本验证，恢复使用测试 Fence Marker 和新 epoch。回退方式为回到验收代码和一份未迁移的独立基线 fixture，迁移历史只读保留，旧未消费授权继续失效。
4. I04 的精确验收提交已核实。若 Core 需要直接依赖其实现，确认采用独立分支上的原 crate 或由负责人指定组合基线。当前 S0 仅保留来源和接口，未合并或复制代码。

## 分阶段落点

| 阶段 | 拟新增内容与完成门禁 |
|---|---|
| S1 | Writer 事务适配、追加迁移、只读对账和 fixture 恢复工具。测试完整审计、100 路额度竞争、提交前后故障、已确认与未知分离及 Fence。 |
| S2 | 独立 Core／Broker／Worker／Observer 测试入口及受控 IPC。用双端 OS 核验、角色、序号、generation、超时、重复和断线重连验证。 |
| S3 | 唯一固定 `file.read.v1` fixture 与独立 reader／sentinel。只允许固定参数和预设虚拟目标。 |
| S4 | Launch、Cancel、Result、Reconcile 状态与独立退出证据。验证响应丢失、进程重启、未完成及取消未确认。 |

每阶段先通过本地验收。稳定里程碑独立提交。最终候选再进行完整 Windows CI、证据 ZIP 和 SHA-256 对账。
