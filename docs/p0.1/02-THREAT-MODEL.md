# 威胁模型与攻击路径

AgentGuard V2.0 P0.1 · 修订日期 2026-11-05

## 目的

从攻击者视角分析模型、运行时、适配器、策略、UI、审计和 OS 边界。以下为架构推导及待验证威胁，接口事实引用来源登记。[能力调查](04-AGENT-CAPABILITY-MATRIX.md)

## 结论

安全设计必须同时考虑不可信操作输入与执行方绕过。合作式 Hook 可以阻止受管调用，面对被污染的宿主、全信任插件或同用户恶意进程，需要独立 OS 边界。普通用户态后台进程与哈希链无法独立抵抗同权限攻击者或管理员。

第一版的安全保证绑定精确版本、执行入口和有效沙箱。每次决策输出 coverage 和 unknowns，缺少强制点时拒绝宣称失败关闭。以下残余风险由安全状态明确呈现。

## 资产及数据分级

| 资产 | 安全属性 | 默认策略 |
|---|---|---|
| 项目源代码与用户文件 | 保密性、完整性、可恢复性 | 只授权指定项目和操作，写前预览，备份能力另验 |
| SSH 私钥、API Key、GitHub Token | 机密、可撤销性 | 不采集内容，不允许工具主动探测或上传 |
| 云服务器凭证、数据库密码 | 机密、环境隔离 | 默认禁止生产连接及凭证访问，人工审批不得越硬禁 |
| 系统配置、认证信息 | 完整性、账户控制 | 默认禁止持久安全弱化、身份窃取和提权 |
| 授权数据库与 IPC 密钥 | 防伪造、防重放 | Core 独占、最小句柄、短期许可 |
| 原始操作、日志与回放 | 完整性、隐私、顺序 | 脱敏后落盘、来源分级、缺口显式化 |
| AgentGuard 二进制/策略/更新包 | 供应链完整性 | 签名与发布摘要校验，降级需明确流程 |

## 对手能力

| 等级 | 精确定义 | 本次产品范围 |
|---|---|---|
| T0 | 外部诱导文本，借合法Agent发起操作 | 在已验入口限制危险提议 |
| T1 | 恶意工具、MCP、插件、依赖 | 必须区分受管dispatch和自主执行，后者需C边界 |
| T2-A | 被控制但确实位于受限执行环境的Host | 仅对实际验证资源边界提供保证 |
| T2-B | 相同用户SID和相近IL的恶意进程 | 当前普通用户部署不作全面防御保证，D01待决 |
| T3 | 管理员、内核和宿主OS控制者 | 不纳入现有可兑现运行保证 |

| 攻击能力 | T0 | T1 | T2-A | T2-B | T3 |
|---|---|---|---|---|---|
| 读取 | 经Agent被授权内容 | 工具可见内容，插件依Host权限 | token/ACL/capability允许资源 | 通常可读同用户文件和可获权进程，受实际DACL/保护机制影响 | 系统控制范围 |
| 修改 | 借工具请求 | 自身运行权限内 | 只限实际边界内，需负测 | 同用户可写配置、binary、DB等可能被改 | 可替换程序/策略 |
| 终止 | 诱导退出 | 自身/可获权进程 | Job/进程DACL约束范围 | 常可杀同SID Core/Broker或持句柄延长存活 | 可停服务/系统 |
| IPC | 构造诱导数据 | 伪报payload、抢占入口 | 可访问pipe及句柄仍能攻击parser | 可冒充客户端、抢占pipe、攻击双方 | 可窃取/重定向全部 |
| 用户密钥 | 通过泄露请求 | 依运行权限可能获得 | 不应获Core密钥，需句柄/文件负测 | DPAPI CurrentUser不提供同SID隔离，可能解密或读内存 | 可接管密钥使用 |
| SQLite | 诱导异常事件 | 依可写权限 | 应不能接触Core目录，需验证 | 可篡改/回滚/删除用户级账本 | 可替换底层状态 |
| 注入 | 经解释器诱导 | 同进程插件可直接调用 | 跨进程受实际token/DACL/IL限制，不能假定全部禁止 | 相近IL且有PROCESS_VM_WRITE等权限时可能注入 | 可绕过用户态限制 |
| 绕过Hook | 诱导未覆盖入口 | 直接fs/spawn/MCP自主行为 | 可跳过Hook但仍应受C限制 | 可停Hook、修改配置或使用外部进程 | 可替换强制点 |
| 攻击Core | 输入洪水/畸形内容 | parser/IPC混淆 | 同上，隔离失败可扩大 | 杀进程、读写内存、修改DB/更新包 | 任意控制 |

T2-A的定义需要独立证据证明Host确实处于边界内，不能把普通用户Host改名为受限Host。Job只做生命周期，DACL同SID和DPAPI均不能单独解决T2-B。独立主体/服务可能改善进程、密钥与ledger边界，但需要管理员部署及运维，不能自动保护普通桌面上的用户意图。D01保留此取舍。

## 攻击路径图

~~~mermaid
flowchart TD
  ExternalContent --> Agent
  Agent --> Hook
  Hook --> Core
  Core --> UserIntent
  UserIntent --> Broker
  Broker --> Worker
  Worker --> Resources
  MaliciousPlugin --> DirectOS
  DirectOS --> Resources
  SameSID --> Core
  SameSID --> Ledger
  Observer --> Ledger
  OSBoundary --> Worker
~~~

Hook为模式A，Broker/Worker为B，OSBoundary为C。DirectOS仅当实际纳入边界才受约束，SameSID箭头表示当前残余攻击面。无标签节点与中文说明分开，以保证解析器可验证。

## 安全目标及不变量

G1 未授权操作不能因 AgentGuard 的解释或“未知”等级被自动批准。G2 授权具有主体、目标、参数、次数、时限和撤销条件。G3 先持久记录授权再回复可执行许可。G4 请求、批准、执行、成功分开。G5 失败和缺口可见。G6 监控器没有通用提权或任意命令接口。

G1 在强制边界内作为必须证明的不变量。边界外未接入操作是已记录覆盖缺口，不能以“Core 默认 deny”声称已经阻止。

## 技术依据

DSH 的 Host 插件位于工作区沙箱外，Reasonix runtime Extension 属于 full trust。Codex 部分 Hook 错误可继续。Named Pipe 默认权限和 Windows 同 SID 访问模型要求额外身份防护。[S01、S18、S25、S40、S44–45](13-SOURCE-REGISTER.md)

## 风险

恶意进程可攻击普通用户态监控器，能够联网的 Agent Host 自身也可能泄露上下文。建立工具网关并不自动控制模型连接、浏览器连接器和远端执行。

## 尚未确定的内容

各 Host 能否把全部相关执行放入可靠隔离，GUI 自动化兼容性、强制出站控制、独立审计锚点及审批防伪能力。详细门槛见开放问题。[开放问题](12-OPEN-QUESTIONS.md)


## 保护声明的边界

L2限已验入口显式阻止，可有公开的故障继续限制。L3限OS认证scope，不推定Hook健康。真实七款全L0，所有新增AT41–46未执行。[能力规范](16-PROTECTION-CAPABILITY-CONTRACT.md) [决策D01](P0.1-DECISION-LOG.md)
