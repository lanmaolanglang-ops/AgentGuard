# P0.1重大决策日志

AgentGuard V2.0 P0.1 · 修订日期 2026-11-05

全部5项状态均为待负责人决定。本次采纳可逆的数据与验证合同，未选择新的服务/驱动/管理员部署方案。推荐用于后续评审，不等同批准执行。Q01–Q24技术缺口仍在开放问题登记，下面只聚合重大架构取舍。

## D01 T2-B安全主体与产品承诺

| 项目 | 内容 |
|---|---|
| 问题 | T2-B安全主体与产品承诺 |
| 当前证据 | 普通用户同SID Core/Broker、DACL、Job、DPAPI不能全面隔离本地恶意进程。N01/N12/N13为E1，AT41未执行。 |
| 可选方案 | 普通用户同SID部署且明确限制范围。独立低权限服务账户或受保护服务边界。VM内运行整体工作环境。 |
| 主要风险 | 服务需管理员安装、账户/IPC/更新维护，GUI意图仍在普通桌面。VM增加资源及使用成本。 |
| 推荐方案 | 先用合成VM完成AT41边界刻画，保持普通用户方案限制声明，待负责人决定是否承担服务成本，不能发布T2-B防御承诺。 |
| 是否阻塞开发 | 不阻塞P1-A。阻塞T2-B防御路线和相应公开承诺。 |
| 后续实验 | I07-A比较进程终止/读内存/IPC/DB/密钥能力，独立主体候选需独立授权后实验。 |

## D02 Windows网络强制backend与权限

| 项目 | 内容 |
|---|---|
| 问题 | Windows网络强制backend与权限 |
| 当前证据 | AppContainer/LPAC、Firewall/WFP和原生sandbox具备机制证据E1，WFP OPEN不等于ADD。14类旁路均待实测。 |
| 可选方案 | 受控无直连Worker加typed Network Broker。经管理权限部署Firewall/WFP。复用逐版本原生网络边界。VM整体网络策略。 |
| 主要风险 | 系统规则权限、IPv6/UDP/loopback/既有连接与规则冲突，现有Host可能不兼容。代理单独不能阻止直连。 |
| 推荐方案 | 优先比较无直连Worker加Broker，按NEXP01–06验证，暂不选定Firewall/WFP/服务或域名全面白名单承诺。 |
| 是否阻塞开发 | 不阻塞请求Schema/代理合成工程，阻塞network OS证书和依赖网络强制的自动许可。 |
| 后续实验 | I07-A/B与AT43/44验证双栈、DoH/QUIC/代理、DNS重绑、redirect/body、socket继承与连接撤销。 |

## D03 GUI兼容与桌面/COM隔离

| 项目 | 内容 |
|---|---|
| 问题 | GUI兼容与桌面/COM隔离 |
| 当前证据 | N01建议不同desktop，UIPI主要限制跨IL，N16说明UIA/UIAccess条件。七款GUI组合没有实验。 |
| 可选方案 | 保留现有桌面与有限A模式。独立desktop/window station的受限Worker。隔离VM。特定UIAccess共享方案。 |
| 主要风险 | 隔离桌面破坏UIA/消息/Clipboard/OLE/拖放，放宽COM/共享浏览器登录态可能引入全权限代理。 |
| 推荐方案 | 先测19中17项矩阵与合法功能对照，每款单独范围。兼容失败时只公布已验A/L1，任何UIAccess/共享方案另审。 |
| 是否阻塞开发 | 不阻塞P1-A，阻塞GUI隔离证书和依赖该出口的强声明。 |
| 后续实验 | ISO04/05/06、AT42验证消息、UIA、COM外部激活、剪贴板与shell实际执行身份。 |

## D04 首个真实B委托Agent、recipe与Shell范围

| 项目 | 内容 |
|---|---|
| 问题 | 首个真实B委托Agent、recipe与Shell范围 |
| 当前证据 | 七款只有各自接口静态证据，B端到端全部未验证。typed文件recipe可设计但产品是否提供替换执行点未知。 |
| 可选方案 | 先选择具有真正tool替换合同的产品和只读file.read。引入file.write/network typed recipe。任意process/Shell作为独立高级路线。 |
| 主要风险 | 工具可能双重执行、身份Prepare后变化、持久stdin和shell解析不可预测。任意recipe使Broker成为权限代理。 |
| 推荐方案 | 先收敛一个版本与一个结构化只读recipe，默认关闭延后自动认领和任意Shell连续许可，由负责人选定实际产品。 |
| 是否阻塞开发 | 不阻塞协议/合成Broker，阻塞真实委托自动执行与强参数/单次认证。 |
| 后续实验 | I06及目标Adapter验证prepare、原生执行替换、最终参数、nonce、断线重提议与AT17/19/30/44/45。 |

## D05 密钥存储、防回退与独立锚点

| 项目 | 内容 |
|---|---|
| 问题 | 密钥存储、防回退与独立锚点 |
| 当前证据 | DPAPI CurrentUser只提供静态保护，user级ledger/epoch可一起回滚。21向量证明字节一致，未证明部署密钥安全。 |
| 可选方案 | 用户DPAPI加最小ACL并限定威胁。独立主体托管。硬件/外部信任锚与离机审计checkpoint。 |
| 主要风险 | 独立主体/硬件/离机依赖增加管理员、运维、恢复和离线可用性成本。信任锚同用户可改则防回退无效。 |
| 推荐方案 | Core独占独立域key，先做公开向量与轮换故障验证，明确DPAPI局限。锚点/硬件和最低版本防回退范围交负责人选择。 |
| 是否阻塞开发 | 不阻塞合成密码学，阻塞抗T2-B密钥/DB回退及全面抗篡改发布声明。 |
| 后续实验 | I06/I08/I20-C与AT27/36/41/46验证旧key停用、重启失效、截尾/回滚和更新包降级。 |
