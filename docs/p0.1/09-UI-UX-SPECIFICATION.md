# UI / UX 文字规范

AgentGuard V2.0 P0.1 · 修订日期 2026-11-05

## 目的

让普通用户理解 Agent 正准备执行的操作、真实保护范围和未知信息，并作出有限、可撤销的授权。本文提供文字布局、页面结构和交互状态。

## 结论

采用 Windows 操作型界面。主界面以七款产品和当前审批为中心，浮窗承担低干扰状态，高危弹窗集中回答九个风险问题。用户看到的每条事实都带来源和阶段，绿色仅用于经验证的受限覆盖。

设计方向采用系统字体、克制色彩、标准控件、清晰焦点和稳定数据层次。沿用P0已有系统控件、字体和无障碍文字规范，本次修订状态语义。

## 四级保护状态

| 等级 | 固定文案 | 当前有效条件 |
|---|---|---|
| L0 | 未接入 | 同scope无有效观察/前置/OS认证 |
| L1 | 事件观察已验证 | telemetry_verified=true |
| L2 | 指定入口的执行前阻止已验证 | pre_execution_block_verified=true |
| L3 | 指定范围的Windows OS隔离已验证 | os_isolation_verified=true |

每行同时显示五项独立标志、scope、client/runtime/adapter/provider/config、证据报告、有效期与fault_behavior。L2不要求OS、参数绑定或单次保证，L3不推定Hook健康。不得显示无范围“整体保护完成”。

合成状态一为“L2 · Bash显式前置拒绝已验 · 参数绑定/单次许可未验 · Hook故障可能继续”。合成状态二为“L3 · Worker文件边界已验 · 网络未验 · Hook不可用”。真实七款全部L0，五标志false，这两个示例不代表实测。

更新或配置变化只使依赖该摘要的认证失效，独立OS证书在确认主体与policy未变后可保留。历史认证保留只读，当前标志从有效证书重新派生。[唯一能力定义](16-PROTECTION-CAPABILITY-CONTRACT.md)

总览的风险计数区分待决、已拒绝、执行后异常和未知结果。拒绝不归类成“已消除风险”。当前任务标签来自 Agent 时标“Agent 提供”，无数据写“未知”，禁止根据进程活跃推断任务完成。

选中 Agent 后右侧详情显示 client/runtime/adapter 版本、连接实例、配置摘要、原生权限、最近测试报告、覆盖/排除路径、事件缺口、当前授权。版本不符时有限授权按钮禁用并给出原因。

历史支持 Agent、会话、工具、阶段、风险和证据过滤。回放按接收时间与因果阶段展示，可暂停、逐事件前进、展开迟到证据。回放中的批准按钮不可用。

## B · 右下角实时监控浮窗

~~~text
┌ AgentGuard   Codex                         [收起] [打开] ┐
│ 任务  整理报表  · Agent 提供                              │
│ 操作  已提出读取 reports 目录                              │
│ 风险  尚未判断        保护  仅观察                         │
│ 需你确认  0 项       最近收到事件 2 秒前                    │
└─────────────────────────────────────────────────────────┘
~~~

默认约 340×170 DIP，可移位并贴近工作区右下角，不覆盖任务栏和系统通知。普通运行不抢焦点，只有新的高危待审批或保护能力下降时通知。通知可合并同一会话的重复提示，但每个具体审批独立保留。

文案使用“已提出读取”“Core 已批准，等待执行证据”“宿主报告成功，尚未独立核验”。收到请求不显示“正在删除”。并发多 Agent 时显示活跃数和当前所选行，不把多个任务混成一个状态。

观察模式出现风险时提示“发现高风险请求，当前无法阻止”，按钮为“查看详情”。“停止 Agent”仅在已经验收的控制接口存在时显示，并回显停止成功、停止失败或未知。

## C · 高危操作居中弹窗

仅为实际等待许可的危险请求弹出。观察发现的事后风险使用风险详情，不伪造一个仍可阻止的批准弹窗。

~~~text
┌ 高风险操作需要决定                                      [查看详情] ┐
│ Claude Code 准备删除项目 cache 目录及其子文件                        │
│ 当前前置拦截范围  Bash · profile xxx · 等待你确认                     │
├ 操作与影响 ────────────────────────────────────────────────────────┤
│ 1 想做什么       递归强制删除 D:\GuardLab\project\cache               │
│ 2 为什么做       Agent 称“清理构建缓存”                              │
│ 3 影响范围       路径解析已核对，文件数/总大小尚未核实                │
│ 4 能否撤销       尚无可用备份证据，通常不经回收站                    │
│ 5 最坏结果       若包含重要文件，可能永久丢失                        │
├ 证据 ──────────────────────────────────────────────────────────────┤
│ 6 已验证         实际工具参数包含 -Recurse 和 -Force                 │
│ 7 Agent 的说法   “这些都是可再生成的缓存”，尚未核验                  │
│ 8 未知           联接目标、内容重要性及恢复副本                      │
│ 9 更安全方案     先只读列出范围，再选择文件或在受控环境中处理        │
├ 原始操作 [展开脱敏参数]     执行身份/工作目录 [展开]                 │
│ [拒绝] [只读预览]                       [仅允许这一次]              │
│                                        [设置有限范围授权]          │
└───────────────────────────────────────────────────────────────────┘
~~~

“已验证参数”仅在来源身份与最终操作绑定满足验收条件时使用，否则标“Hook 报告参数”。示例布局不是本次已完成的真实核验。

只读预览是独立结构化操作，另行按策略授权，不能执行原命令后声称预览。删除预览先生成清单，不在预览中删文件。没有安全预览 recipe 时按钮禁用，解释具体原因。

有限授权展开为 Agent、会话、目录、操作分类、有效期、最大次数、目标和参数限制表单。显示最终自然语言范围及剩余限制，不提供无限制“一律允许”。脚本执行、上传和删除默认最多一次，高风险泛化连续授权不可用。

## 审批交互状态

| 状态 | 展示及交互 |
|---|---|
| 等待解析 | 骨架占位，所有许可按钮不可用 |
| 等待补证 | 显示未知，支持安全只读预览，不能把 spinner 当已核实 |
| 等待用户 | 默认焦点“拒绝”，Tab 顺序稳定，Enter 只作用于当前显式按钮 |
| 用户批准后提交 | 按钮 disabled，显示“正在核对参数和授权”，没有成功动画 |
| 参数变化 | 旧批准失效，列出 command/path/args/cwd/identity 差异，重新提议 |
| 授权成功 | 显示“仅此操作已批准”，后续执行状态单独跟踪 |
| 过期/撤销 | 显示失效原因，关闭不产生许可 |
| UI/Core 失联 | 禁许可，显示“未获得安全决策”，保留未决条目 |
| 原生回退 | 明确标“请在 Agent 原生窗口确认”，只在已验证等待模式启用 |
| 结果未知 | 显示“是否执行尚未确认”，禁止自动重试 |
| 已拒绝仍见副作用 | 显示“拦截异常”，降级并关联独立证据 |

同一操作只能有一个 pending_id。多窗口双击、延迟 UI 回复和历史弹窗提交由 Core 拒绝。审批卡片从 pending 快照渲染，不能被 Agent 后续文本替换。

不允许按截止倒计时自动允许，倒计时归零默认拒绝或回可靠原生审批。允许关闭弹窗收回主界面，后台 pending 不自动变成许可。

原Hook请求已经结束时卡片显示“本次请求已结束，重新提议需重新确认”，原批准按钮禁用。延后自动认领默认关闭，D04确定且同一prepared身份保留、完整验收通过后另启用，不能对A无最终点的入口开放。

## 授权与撤销页面

每条显示范围、主体、剩余次数、到期时间、创建者、来源批准及当前 in-flight。撤销按钮有即时 pending feedback，Core 确认后显示“尚未消费的授权已撤销”。已消费操作单列“取消中/已停止/停止失败/无法确认”，不能写“全部撤销成功”掩盖已发生副作用。

规则创建与危险请求确认分开，避免在审批中默认勾选保存长期规则。过期规则可以查看和复制为新草稿，不能直接复活旧 capability。

## 视觉与无障碍

系统中文字体以 Microsoft YaHei UI/系统 fallback 为主，标题 20–24 DIP、正文 14–16 DIP、辅助信息 12–13 DIP，命令使用可读等宽字体。颜色用蓝色表示操作焦点、琥珀表示待确认/未知、红色表示危险/拒绝、绿色表示经验证状态，均配文字与图标。

文本对比度目标至少 4.5:1，大文字至少 3:1。支持 Windows 高对比度、键盘全操作、屏幕阅读器、可见焦点、减少动态效果。状态变化用适当 live region，不让每条日志打断朗读。提示与关键信息不只依赖颜色。

弹窗不采用 UAC 样式冒充系统可信安全桌面。显示 AgentGuard 名称与来源，普通用户桌面上的防伪能力仍有限。焦点不在后台时不静默批准。长命令、恶意 Markdown、控制字符和双向文本以安全纯文本展示，原始形式可复制但需去除可执行链接。

## 技术依据

保护状态、请求/执行分离与审批字段来自项目需求。界面权限能力依赖 Tauri capability，数据来源和 native timeout 事实见 Agent 调查。[需求](01-PRODUCT-REQUIREMENTS.md) [S01、S07、S35、S37、S51–53](13-SOURCE-REGISTER.md)

## 风险

提示疲劳、普通桌面欺骗、信息过载、未知范围解释不清都可能导致误批准。批量合并只减少通知，不能扩大单条授权范围。

## 尚未确定的内容

Windows DPI/屏幕阅读器实测、非技术用户能否正确区分批准与执行、浮窗遮挡、审批时限和连续授权默认值。可用性目标在测试计划中定义。


## UI与账本对应

grant.created/pending/reserved/consumed与revoked/expired/invalidated/failed用07固定状态，授权消费不显示工具成功。执行状态独立，结果unknown禁自动重跑。I09负责状态投影，I19执行理解与无障碍验收，AT32/37/45覆盖误批及状态一致性。[协议](07-UNIFIED-EVENT-SCHEMA.md) [测试](10-TEST-AND-ACCEPTANCE-PLAN.md)
