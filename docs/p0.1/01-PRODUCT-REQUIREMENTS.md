# 产品需求与验收追踪

AgentGuard V2.0 P0.1 · 修订日期 2026-11-05

## 目的

把用户需求转为可验证的产品合同，覆盖 Windows 11 的七款 Agent 管理、自然语言解释、确定性风险判断、有限权限、审计与状态展示。

## 结论

产品首版提供七款固定管理入口，能力按实际证据分级。观察、建议、阻止、原生审批接管和 OS 隔离各自核验。默认普通用户运行、数据本地最小化、确定性授权优先。核心安全断言限于已验证的执行入口和资源边界。

## 目标用户与任务

普通用户让Agent完成整理文件、代码修改、报表生成、构建和资料处理等连续工作，需要看懂操作、知道能否撤销，并限制影响范围。专业用户可查看原始脱敏参数、进程身份、规则与证据链。

AgentGuard负责监督与可验证权限管理，模型和Agent运行由原产品承担。项目不要求训练或默认运行本地大模型。

## 监控目录与数据来源

| 行为 | 首选语义来源 | 可选独立佐证 | 无接口/证据时 |
|---|---|---|---|
| 当前任务 | 用户输入或Agent任务事件 | 会话关联 | 标未知或Agent提供，不猜测 |
| 模型工具调用 | pre/call lifecycle | dispatch与工具body记录 | 标覆盖缺口 |
| Shell命令 | 同步前置工具事件 | 进程启动、实际argv | 无完整argv则禁强绑定 |
| 文件读取 | 受管工具请求/结果 | 受限broker或获授权sensor | 不承诺全量读取审计 |
| 文件修改 | 工具参数与patch/result | 前后摘要、文件identity | 区分自报和已核验 |
| 文件删除 | 删除提议与结果 | 清单/前后状态/恢复副本 | 结果不明写unknown |
| 网络访问 | 工具/MCP调用 | 受控网络sink、获授权OS事件 | 域名声明不等同已连接/上传 |
| 程序启动 | 受管spawn请求 | PID+创建时间+Job | 关联仅推断时标明 |
| MCP调用 | tools/call等Agent lifecycle | dispatch/服务日志 | server自主行为另列范围 |
| 插件执行 | 插件/工具事件、注册generation | 可用进程/资源观察 | 同进程插件旁路列风险 |
| 子Agent | subagent/session树事件 | 新进程/外部backend identity | 不继承父保护假设 |
| 权限申请 | PermissionRequest或原生协议 | Core pending/用户决策记录 | 原生UI可见不代表可接管 |
| 操作结果 | post/result与结构化错误 | 独立副作用核验 | claimed、observed、verified分级 |

来源差异与已证实能力参见七款调查，以上数据源为候选设计，不表示所有Agent提供全部字段。[能力矩阵](04-AGENT-CAPABILITY-MATRIX.md)

## 状态与授权不变量

NR01 未知风险、未知身份、过期许可不得自动允许。NR02 操作参数或上下文改变须重新批准。NR03 Core不能成为任意命令/提权代理。NR04 UI失效不使新危险操作获得许可。NR05 在真实强制入口内故障默认关闭。NR06 事件丢失、强制点不可用和覆盖例外始终可见。

对NR02/05，产品必须验证最终执行点和host错误行为。只具备fail-open Hook时不能宣布满足这两项强保证，相关profile只按实证给出有限入口认证，并披露故障行为。L2本身不要求参数绑定、单次许可或OS隔离。

## 有限授权的用户合同

单次批准仅适用精确操作。目录授权同时限定操作分类、时限、次数、Agent和会话。批准父命令不会成为无限制terminal输入或子进程权限。撤销阻止尚未消费的后续操作，对已运行操作报告可取消程度与真实结果。

高风险默认每次人工确认。极高风险的硬禁不提供绕过按钮。原生回退只能等待人类的真实确认，不能落入原生full-access/auto许可。

## 数据、隐私与本地默认值

默认保存脱敏事件和解释，不采集凭证正文，不保存用户文件全量副本。导出由用户触发并预览脱敏范围。Agent本身的云请求由原产品决定，AgentGuard日志本地存储不能推导出所有任务数据都留本地。

建议初始审计保留30天且总量1GiB，授权记录及封口段按可审查保留规则管理。达到上限时先清理符合保留策略的历史观察段，关键决策无法持久保存则停止新许可。保留天数/容量均为待P1确认的产品参数，不是当前实施设置。

UI只展示必要短文本，原始敏感上下文在决策内存中短期存在。调试和crash dump不能默认包含完整命令秘密，日志模板与错误链均测试脱敏。

## P0 工作范围与实际执行

P0.1仅修订Markdown，执行只读公开来源检查、Schema/夹具/密码学及文档一致性验证。没有软件安装、业务代码实现、Agent配置变更或Windows隔离实验。原P0的历史来源和元数据保留，当前来源可达性另列。

三种路线为A原生Hook前置阻止、B委托Broker、C独立OS限制，分别认证。七款目前全部L0且五标志false。有限连续授权必须同时具有已验证最终参数绑定、单次消费、B委托路线、原生allow及所需资源强制边界，缺条件禁用。
